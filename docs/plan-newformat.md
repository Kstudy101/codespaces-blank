## 1. 지시서가 위임한 결정 (§1-1 "구현자가 정하고 완료 보고에 명시")

### 1-1. 통 분할 — ❓+🍀는 꼬리통, 아침 묶음의 맨 끝

```
1통  📘 Day N : 문법  / [일본어부] / 🔗 接続 / 💡 学習ポイント / 💬 회화 3행
2통  📚 今日の単語 (품사 2·2·2)
꼬리통  ❓ 今日のクイズ + ①②③ + 🍀 今日のひとこと + quickReply(①②③)
```

push-daily 가 꼬리통을 뽑아 **운세·부적·예고 뒤(묶음 맨 끝)** 에 다시 붙인다.

**이유.** quickReply 는 묶음의 마지막 1통에서만 열린다(기존 절목 퀴즈가 말미로
가는 이유와 동일 — push-daily 주석). ❓를 2통 안에 넣으면 운세가 뒤에 오는 순간
답 버튼이 화면에 안 나온다. "quickReply 버튼은 기존 quizMessage 방식 그대로"를
지키려면 퀴즈를 나르는 통이 말미여야 한다. 🍀가 ❓ 뒤(스케치 순서)이므로 같은
통에 태운다 — 부수 효과로 bridge 는 이동 전과 같은 "아침의 맨 끝" 위치를 되찾는다.

- 1통·2통은 현행 분할 그대로(문법·회화 / 단어).
- 구양식(꼬리통 없음)에서 bridge 는 **레슨 마지막 통(2통) 말미**에 붙는다.

### 1-2. 데일리 ❓는 신양식 원고에서만

구양식 원고(현재 시드된 303일 전부)는 quiz 가 있어도 데일리 ❓를 만들지 않는다.
현행 거동(3의 배수 복습·절목만) 유지.

**이유.** 지시서 §6-1 이 배포① 시점의 화면 변화를 "헤더가 붙고 bridge 위치
이동"으로 못박았다. 구양식에도 ❓를 붙이면 세 번째 변화가 생긴다. §1-2 표의
"quiz 없음 → 퀴즈 섹션 생략 (현행과 동일)"도 같은 방향.

- 신양식 아침: 데일리 ❓가 붙고, 3의 배수 복습 뽑기는 **쉰다** (같은 아침에
  퀴즈 2건 금지 — 절목·예고와 같은 기존 원칙).
- 절목(30/50/75) 아침: 데일리 ❓를 접고(🍀는 2통으로) 절목 퀴즈가 말미.
  기록(action=quiz)이 무보존(action=review)에 밀리면 안 되기 때문.
- 데일리 ❓의 postback 은 **기존 review 방(무보존·즉시 채점)** 을 그대로 쓴다.
  `action=review&day=N` — 새 방을 만들지 않는다.

### 1-3. 통수 상한 (LINE 5통)

| 아침 | 구성 | 통수 |
|---|---|---|
| 신양식 보통 | 1·2통+운세+부적+❓ | 5 |
| 신양식+예고 | 1·2통+운세+예고+❓ (부적 쉼) | 5 |
| 신양식 절목 | 1·2통(🍀)+운세+부적+절목 | 5 |
| 절목+예고 | 1·2통(🍀)+운세+예고+절목 (부적 쉼, 현행 동일) | 5 |
| LINE 직접(운세 없음) | 1·2통+❓ | 3 |

부적의 `<5` 판정은 꼬리통을 셈에 넣는다(`messages.length + (quizTail?1:0) < 5`).

### 1-4. 문면 세부 (예시문 부재 시 스케치 직역)

- 대화 행: `{who}：{kr}` + 다음 행 `  （{ja}）` (2칸 들여쓰기·전각 괄호).
  구양식도 동일 적용 — 대화는 양식 공통 필드라 §1-2 표의 분기 대상이 아니다.
- 단어 행: `【名詞】 1. {kr}　{meaning}　2. …` (품사당 1행,
  `【名詞】`·`【動詞】` 뒤 반각 공백 1 — 스케치의 폭 맞춤 그대로).
- ①②③는 현행 quizMessage 그대로 **행마다 1개** (스케치의 1행 나열은 축약 표기로 읽음).
- `grammar_point` 분해: 말미 전각 `（…）`를 일본어부로. 없으면 `[…]` 행 생략.
- tip 분해: 행머리 `形`/`使`/`落`(+공백)으로 버킷 분류, 접두어는 떼고 출력.
  이어지는 무표지 행은 직전 버킷에 붙는다. 3버킷이 다 없으면 구양식으로 간주.

### 1-5. pos 표기는 한 곳 (§2-3)

`render.mjs` 의 `POS = ["名詞","形容詞","動詞"]` 가 유일한 정의.
분류 키(원고의 `pos` 값)이자 표시 헤더(`【名詞】`)로 코드가 쓴다.
content-check 는 이것을 import 한다.

### 1-6. usableQuiz 이동

퀴즈 형 검사는 `render.mjs` 로 옮기고 `repo/learning.mjs` 가 재수출한다
(기존 `learning.usableQuiz` 호출부 무변경). 렌더러가 꼬리통을 만들 때
같은 판정이 필요한데, render→repo 방향의 import 는 층을 거꾸로 타기 때문.

### 5-1 교체 대상과 후보 ([plan-lesson-format-v2](plan-lesson-format-v2.md) §4 조사 기반)

병행 조사에서 「이 상 없음」 군집은 지시서가 본 3개(37·39·41)가 아니라

41은 완전 동의어다. **37을 남기고 39·41을 교체**하는 것을 권한다.

### 7-6 1통/2통 분할 결정 (§1-1)

  꼬리통을 셈에 포함. 예고·절목 아침엔 데일리 ❓를 접어(quizSection:false) 재구매
