## 구조 (한 문장)

**부적이 매일 바뀌는 것은 입력(cat)이 바뀌기 때문이지, 부적이 날짜를
보기 때문이 아니다** — `amulet.js` 는 날짜를 모른 채 그대로이고
(`verify-amulet` 의 「날짜를 바꿔도 같은 한 장」 관문 무손), 서버가
그날 운세의 **가장 낮은 항목**(`rankCats(scores).bottom` — 운세 본문의
「いちばん低い」와 같은 함수)을 골라 `/amulet?cat=…` 에 실어 보낸다.

## 흐름

```
아침 배신: 본문 2 + 운세 + 부적 권유(Flex·uri 버튼)   ← 눌러야 만들어짐
[お守りを受け取る] 탭 → 사이트 /amulet?cat=<bottom> → 그 자리에서 1장
```

- 운세가 붙은 아침에만 (부적은 운세 문맥의 연장). 예고+절목이 겹친
  5통 아침은 부적이 쉼 (LINE 상한 5 — 전체 400 방지)
- URL 에는 cat 만 — 생년월일·이름·id 없음 → privacy 개정 불요.
  같은 링크 재방문 = 같은 한 장 (「그날의 부적」 재현으로 옳음)
- 동점은 CAT_IDS 순서를 2차 기준으로 결정론 (지시⑪ §2-2 잠재 결함 봉인)
- 문면 (2026-08-06 대표 확정): altText 「🔮 きょうの特別なお守り」 /
  본문 「今日の運勢を補う「お守り」をご用意しました。不足している
  運気を整えます。」 / 버튼 「お守りを受け取る」
- 배부: **매일** (대표 확정 A). 누른 것 무측정 (2026-08-04 원칙)
- 폴백: 부적 조립 실패 시 부적만 조용히 빠지고 운세·본문 정상 (§4-5)

## 배포 순서 (엄수됨)

⑨(저녁 Flex 규칙) → 사이트(`?cat=` 수신) → 서버(버튼 발신). 역순이면
버튼이 파라미터를 모르는 페이지로 이용자를 보낸다.
