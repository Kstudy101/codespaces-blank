
- **`.htaccess`가 확장자 없는 URL을 처리**. 새 페이지 `omikuji.html`은 `/omikuji`로 접근됨 (별도 설정 불필요)

  - 한자어 수사 변환 (`1995 → 천구백구십오`)
  - 받침 판정 → 조사 자동 선택
  - Canvas 공유 카드 생성 (1080×1350) + SNS 공유 경로

## 3. 사주 엔진 — KASI API가 필요 없는 이유

원안은 KASI에서 **일별 간지**를 받아 테이블로 만듭니다. 하지만 사주 4주는 성질이 다릅니다.

| 기둥 | 계산 방법 | 외부 데이터 필요? |
|---|---|---|
| **일주(日柱)** | 기준일로부터의 경과일 `% 60` | **불필요** — 순수 산술 |
| **연주(年柱)** | 입춘 경계로 연도 판정 후 `% 60` | 절기 시각만 필요 |
| **월주(月柱)** | 12절(節) 경계로 월 판정 | 절기 시각만 필요 |
| 시주(時柱) | 일간 + 시진 | 불필요 (진태양시 보정 시 경도 필요) |

즉 **필요한 외부 데이터는 24절기 시각뿐**입니다.

```
원안:   1930~2030 일별 간지   = 36,900행  ≈ 1.1MB (gzip 200KB)
개정:   1930~2030 절기 시각   =  2,424행  ≈  40KB (gzip 12KB)
```

절기 시각은 **태양황경이 15° 배수가 되는 순간**으로 정의되며 천문 계산으로 구합니다.
간이 VSOP87 수준이면 오차 1분 이내로, 절기 경계 판정에는 충분합니다.

### 산출물

```
tools/build-solar-terms.py   →   solar-terms.json
```

- 오프라인 계산. **API 키·시크릿·PR 검토 흐름 불필요**
- `tools/build-kanji-json.py`와 동일한 패턴(로컬 실행 → 결과 커밋)

### 검증 (필수)

절기 시각과 **일주 기준일(epoch)** 은 틀리면 모든 결과가 어긋나므로, 구현 전에 먼저 확정하고 검증합니다.

1. 공표된 절기 시각(한국천문연구원 역서, 일본 국립천문대 暦要項)과 **연 24개 × 표본 10개년** 대조 — 허용 오차 ±2분
2. 일주 epoch를 **서로 다른 만세력 3곳**과 대조. 임의 날짜 20건 일치 확인
3. 절기 경계 전후 1일 케이스(입춘·경칩 등)에서 월주가 올바르게 넘어가는지

> **이 검증이 끝나기 전에는 콘텐츠 구현에 들어가지 않습니다.** 계산이 틀린 채로 문구를
> 얹으면 나중에 전부 다시 만들어야 합니다.

### 시주(時柱) — 포함 확정

**결정: 포함한다.** 다만 비용을 정확히 알고 시작해야 합니다.

시주는 「일간 + 시진」이라는 단순한 표 조회로 끝나지 않습니다. 정확히 하려면 세 가지가 붙습니다.

| 보정 | 내용 | 검증 난이도 |
|---|---|---|
| **진태양시** | 출생지 경도와 표준자오선(135°E)의 시차. 서울 기준 약 −32분 | 중 — 도시별 경도 표 필요 |
| **서머타임** | 한국 1948~51, 1955~60, 1987~88년 시행. 해당 기간 출생자는 1시간 보정 | 낮 — 기간 표 내장 |
| **조자시/야자시** | 23:00~24:00을 당일로 볼지 다음날로 볼지. 유파에 따라 다름 | 낮 — 옵션 플래그 |

**설계 방침**

- 시주 로직을 **별도 파일로 분리**합니다. 계산 오류가 나도 연·월·일주는 영향받지 않도록
- 출생 시각을 **모르는 사용자가 다수**입니다. 「시간 모름」 선택지를 반드시 두고,
  선택 시 시주를 빼고 3주로 계산 + 화면에 그 사실을 표시
- 진태양시 보정은 **주요 도시 목록 선택**으로 처리(경도 직접 입력 없음).
  일본 거주자가 대부분이므로 일본 도시도 포함해야 합니다 — 도쿄(139.7°E)는 +19분으로
  한국과 부호가 반대입니다
- 조자시/야자시는 기본값을 하나 정해 고정하고, 옵션 노출은 하지 않습니다
  (일반 사용자에게 설명 불가능한 선택지)

**추가 검증 항목** (§3 검증에 더해)

4. 서머타임 시행 기간 경계일(1948-06-01, 1988-10-09 등) 전후 케이스
5. 23:00~01:00 출생 케이스에서 일주가 기준대로 갈리는지
6. 서울·부산·도쿄 출생 각각에서 진태양시 보정 부호와 크기가 맞는지

## 4. 저장 정책 — 결정과 그로 인해 생긴 충돌

**결정: 생년월일은 A(저장하지 않음). 단어장·출석은 만든다.**

이 두 결정은 그대로는 양립하지 않습니다. 단어장과 출석 스탬프는 **저장이 있어야
존재할 수 있는 기능**이기 때문입니다. 어제 모은 단어가 사라지는 단어장, 연속 일수가
초기화되는 출석부는 기능이라 부를 수 없습니다.

### 해석 — 무엇을 지키려는 약속인가

이 사이트의 프라이버시 문구가 지키려는 것은 **입력된 개인정보**입니다.

> 「入力されたお名前・生年月日は保存されません」

이름과 생년월일은 개인을 특정할 수 있는 정보이고, 일본인 사용자가 입력을 망설이는
대상입니다. 반면 **사용자가 스스로 모은 한국어 단어 목록**과 **방문한 날짜**는
성격이 다릅니다. 학습 이력이지 신원 정보가 아닙니다.

따라서 다음과 같이 나눕니다.

| 데이터 | 저장 | 근거 |
|---|---|---|
| 이름·후리가나 | **저장 안 함** | 개인 식별 정보. 현 약속 유지 |
| 생년월일·출생시각 | **저장 안 함** (A) | 동일 |
| 단어장(모은 단어) | 기기에 저장 | 학습 이력. 사용자가 명시적으로 「저장」을 누른 것만 |
| 출석 기록(날짜 목록) | 기기에 저장 | 학습 이력 |

### 폴리시를 반드시 고쳐야 합니다

현재 문구는 **뭉뚱그린 부정**이라 이 구분을 담을 수 없습니다.

```
현재 (privacy.html 1항):
  「Cookie・localStorage 等への保存も行いません」   ← 단어장을 만드는 순간 거짓
```

→ 대상을 명시하는 문구로 바꿉니다.

```
개정안:
  診断機能に入力されたお名前・ふりがな・生年月日は、保存されません。
  一方、単語帳に保存された単語と出席の記録は、お使いの端末（ブラウザ）の中に
  保存されます。これらはサーバーへ送信されず、運営者が見ることはできません。
  「保存した単語をすべて削除」からいつでも消去できます。
```

**전량 삭제 버튼은 필수입니다.** 저장한다고 적어놓고 지울 방법을 주지 않으면
약속의 절반만 지키는 것이 됩니다.

> GA4·Clarity 때와 같은 패턴입니다 — 저장 기능을 넣는 커밋에서 폴리시를 함께
> 고치지 않으면, 폴리시가 그 순간부터 거짓 문서가 됩니다.

### A와 「매일 재방문」의 마찰 — 남은 결정

생년월일을 저장하지 않으므로, **오늘의 운세를 볼 때마다 생년월일과 출생시각을
다시 입력**해야 합니다. §5의 목표가 「매일 돌아오게 만드는 진입점」인데,
매일 생년월일시를 타이핑하게 하면 그 목표와 정면으로 부딪힙니다.

시주까지 포함하기로 했으므로 입력 항목은 **연·월·일 + 시·분**입니다. 적지 않습니다.

선택지:

| 안 | 내용 | 성격 |
|---|---|---|
| **A 그대로** | 매번 입력 | 약속은 가장 강하다. 매일 재방문 목표는 약해진다 |
| **A + 옵트인** | 기본은 저장 안 함. 「この端末に記憶する」 체크를 **사용자가 켰을 때만** 저장 | 침묵 저장이 없다는 A의 취지는 유지. 원하는 사람만 편해진다 |

**A + 옵트인을 권합니다.** A가 막으려던 것은 「사용자 모르게 저장되는 것」이지
「사용자가 원해서 저장하는 것」이 아닙니다. 단어장·출석을 이미 저장하기로 한 이상,
저장 기능 자체는 존재하게 되므로 일관성 면에서도 자연스럽습니다.

다만 이건 **최종 확인이 필요한 사항**입니다. A를 문자 그대로 유지하시겠다면
그대로 진행하되, 오늘의 운세의 재방문 효과는 기대치를 낮춰 잡아야 합니다.

## 5. 페이지 구성

라우터가 없으므로 **독립 HTML**로 만듭니다. `.htaccess`가 확장자 없는 URL을 처리하므로 추가 설정은 없습니다.

| 파일 | URL | 성격 |
|---|---|---|
| `omikuji.html` | `/omikuji` | おみくじ × 토정비결 — **랜덤 추첨** 체험 |
| `gilbang.html` | `/gilbang` | 恵方 × 길방 — **방위** 진단 |
| `amulet.html` | `/amulet` | 오행 부적 메이커 — **제작·다운로드** |
| `index.html` (수정) | `/` | 상단에 「오늘의 운세」 위젯 — **입구** |
| `words.html` | `/words` | 단어장 목록·삭제 |

역할이 겹치지 않도록 성격을 분리합니다 (원안의 구분을 그대로 채택):

- **오미쿠지** = 매번 결과가 다른 추첨 (문화 비교가 목적)
- **길방** = 오늘/올해의 길한 방위
- **오늘의 운세** = 내 사주 기반 일일 종합운

### 공통 구현 방침

- `page.css`를 공유하고, `.tip` 컴포넌트처럼 **재사용 가능한 부품**으로 스타일 추가
- 각 페이지에 AdSense·GA4·Clarity 3종 태그 (404 제외 규칙과 동일)
- canonical·OG·sitemap 등록 — `tools/set-site-url.py`의 `TARGETS` 배열에 새 파일 추가 **필수**
  (빠뜨리면 도메인 이전 시 그 페이지만 옛 호스트를 가리킴)
- `tools/build-site.sh`의 `PUBLIC` 배열에 추가 **필수** (안 하면 배포되지 않음)

### 크롤러 대응

이 사이트의 콘텐츠는 JS로 생성되므로, AdSense 심사에서 **빈 페이지로 보이는 문제**를 이미 한 번 겪었습니다.
새 페이지도 같은 함정이 있습니다.

→ `index.html`의 `#about`처럼, 각 페이지에 **입력 전에도 읽히는 정적 해설**을 반드시 넣습니다.
「오미쿠지란 무엇인가 / 토정비결이란 무엇인가 / 둘의 차이」 같은 문화 해설은
그 자체로 좋은 콘텐츠이면서 크롤러 대응이 됩니다.


```js
    { w: "-소서",     m: "祈願を表す古語の語尾" }
  ],
  grammar: "「-소서」は古い祈願文の終結語尾。現代の「〜してください」の格式体にあたります。"
}
```

- `topikLevel` 제외 — 기존 레벨 체계가 없어 붙일 기준이 없음
- `audio` 제외 — `SpeechSynthesis`로 대체

### 단어장 요구사항

- 중복 저장 방지 (같은 `korean` 키)
- 목록 페이지 `/words` — 저장한 단어 확인·개별 삭제·**전량 삭제**
- 저장 개수 상한을 둘 것 (localStorage 용량 초과 시 조용히 실패하면 안 됨)

## 7. 몰입 구조 — 오늘의 운세를 입구로

**결정: 오늘의 운세를 먼저 만들고, 거기서 다른 콘텐츠로 끌고 간다.**

### 의존 관계 — 순서가 강제됩니다

오늘의 운세는 사주 기반이므로 **계산 엔진이 먼저**입니다. 검증되지 않은 계산 위에
입구 기능을 얹으면, 나중에 계산을 고칠 때 입구부터 다시 만들게 됩니다.

```
절기·일주 검증 통과  →  오늘의 운세  →  길방 · 부적
                          │
                          └─ 오미쿠지 (엔진 불필요, 언제든 병행 가능)
```

### 하루의 동선

매일 돌아오게 만드는 것이 목표이므로, **하루에 한 번 완결되는 고리**를 만듭니다.

```
① 홈 상단 「오늘의 운세」
   생년월일시 입력 → 오늘의 총운·재물·애정·건강
        ↓  결과 문구에서 핵심 어휘 3~5개
② 어휘 카드 — 뜻풀이 · 발음 재생 · 「단어장에 저장」
        ↓
③ 출석 스탬프 적립 — 「연속 N일」 표시
        ↓  다음 행동 제안 (오늘 운세 내용에 맞춰 분기)
④ ・재물운이 낮다  → 「부적을 만들어 보세요」   → /amulet
   ・이동운이 좋다  → 「오늘의 길한 방위는?」    → /gilbang
   ・가볍게 한 번 더 → 「오미쿠지를 뽑아보세요」  → /omikuji
```

**④의 분기가 핵심입니다.** 모든 사용자에게 같은 링크를 나열하면 그냥 메뉴지만,
**오늘의 결과에 맞춰 다른 것을 권하면** 이어서 볼 이유가 생깁니다.

### 몰입을 만드는 장치

| 장치 | 내용 | 근거 |
|---|---|---|
| **하루 1회 제한** | 오늘의 운세·오미쿠지는 하루 한 번 | 다시 뽑을 수 있으면 결과의 무게가 사라짐 |
| **연속 일수** | 「3일 연속」 표시 | 끊기 아까움이 재방문 동기 |
| **어제와 비교** | 「어제보다 재물운 ↑」 | 어제 온 사람에게만 보이는 정보 |
| **단어 누적** | 「지금까지 42단어」 | 학습 성과의 가시화 |
| **미완성 표시** | 「오늘 아직 안 뽑은 것: 오미쿠지」 | 마무리하고 싶게 만듦 |

> **주의** — 이 장치들은 전부 §4의 저장 결정에 걸립니다.
> 「연속 일수」와 「어제와 비교」는 **어제의 기록이 남아 있어야** 성립합니다.
> 출석은 저장하기로 했으므로 연속 일수는 가능하지만,
> **「어제와 비교」는 어제의 운세 결과를 저장해야 하므로 A와 충돌**합니다.
> 생년월일을 저장하지 않으면 어제 결과를 재현할 수도 없습니다.
> → §4의 「A + 옵트인」이 정해지면 가능, A 그대로면 이 장치는 제외.

### 단계

**1단계 — 계산 기반** (콘텐츠 없음)
```
tools/build-solar-terms.py    절기 시각 생성
solar-terms.json              산출물
docs/saju-verification.md     검증 결과 기록
```
§3 검증 6종 통과가 완료 조건. UI는 만들지 않습니다.

**2단계 — 오늘의 운세 + 학습 부품**
```
study.js         단어장·출석·발음 (공용, 신규)
index.html       상단 위젯 + 온보딩
words.html       단어장 목록 (/words)
privacy.html     저장 관련 폴리시 개정 ← 같은 커밋에서
```

**3단계 — 오미쿠지** (엔진 불필요, 1·2단계와 병행 가능)

**4단계 — 길방**

**5단계 — 부적 메이커**
- 폰트는 **시스템 폰트로 시작**합니다. 현재 사이트는 외부 폰트 요청이 0건이고,
  캘리그래피 웹폰트는 한글 전체를 담으면 수 MB입니다
- 고품질 폰트를 외부 API로 유료 제공하는 구상은 **서버가 필요**합니다.
  현재는 정적 호스팅(Xserver)뿐이므로 별도 스코프로 둡니다

## 8. 남은 결정

1. **「A + 옵트인」을 채택할지** (§4) — 채택하면 「어제와 비교」 등 재방문 장치가 살아납니다.
   A를 문자 그대로 유지하면 그 장치들은 빠집니다
2. **조자시/야자시 기본값** — 유파에 따라 다릅니다. 하나로 고정하고 노출하지 않을 예정
3. **하루 1회 제한의 리셋 시각** — 자정(로컬 시간) 기준으로 할지, 한국 시간 기준으로 할지

## 9. 검증 계획

기존 방식을 그대로 씁니다 — jsdom 단정문 + 실제 배포 후 스모크 테스트.

| 대상 | 방법 |
|---|---|
| 절기·일주 계산 | 공표 자료 대조 (§3) |
| 페이지 구조·링크·메타 | jsdom (`chk.js` 패턴) |
| 어휘 카드 조사 처리 | 받침 유무별 케이스 |
| 정적 콘텐츠 분량 | JS 미실행 시 본문 글자 수 측정 |
| 시주 보정 | 서머타임 경계·23시대 출생·도시별 경도 (§3 검증 4~6) |
| 단어장 | 중복 저장 방지 · 전량 삭제 · 용량 초과 처리 |
| 출석 | 자정 넘김 · 연속일수 계산 |
| 폴리시 정합 | 저장하는 것과 폴리시 기재가 일치하는지 (도구 추가 시 필수 확인) |
| 배포 | `tools/build-site.sh` + Actions 스모크 테스트에 새 URL 추가 |

**스모크 테스트에 새 페이지 URL을 추가하는 것을 잊지 말 것** —
`/omikuji`, `/gilbang`, `/amulet`이 200을 반환하는지 확인해야 `.htaccess` 누락을 잡습니다.

## 10. 원안 대비 요약

- **KASI API·시크릿·전용 워크플로 — 불필요.** 절기 시각만 있으면 되고 오프라인 계산 가능

- **저장 범위를 나눔** — 이름·생년월일은 저장 안 함(A), 단어장·출석은 저장.
  **폴리시를 같은 커밋에서 개정해야 함**
- **시주 포함 확정** — 진태양시·서머타임·조자시 보정 포함. 「시간 모름」 선택지 필수,
  검증 항목 3종 추가
- **학습 모듈 전부 신규** — `study.js` 공용 파일로. 발음은 `SpeechSynthesis`(외부 요청 0)
- **오늘의 운세를 입구로** — 결과에 따라 다음 콘텐츠를 분기 제안하는 구조
- **부적 폰트는 시스템 폰트로 시작** — 유료 고품질은 서버가 필요하므로 별도 스코프
- 문화 비교·역할 구분·어휘 스키마 등 **원안의 콘텐츠 설계는 대부분 그대로 유효**
