# P4 계획서 — 101일 콘텐츠 & 배포 배치

작성: 2026-08-03 / 선행: [research.md](research.md) · [plan-fortune-content.md](plan-fortune-content.md) §11

> 이 문서는 **계획**입니다. 승인 전까지 콘텐츠도 코드도 쓰지 않습니다.

---

## 1. 조사 결과 — P4 는 「원고 작성」만이 아닙니다

`content_templates` 가 0건이라 「101일분 글쓰기」로 보이지만, 조사해 보니
**보낼 수단 자체가 없습니다.**

| 있는 것 | 없는 것 |
|---|---|
| `content_templates` 스키마 | 행 **0건** |
| `learning.upsertTemplate()` 입고 API | 입고 스크립트 |
| `learning.getTemplate()` 조회 API | **{NAME} 치환 코드** |
| `line.pushMessage()` 발신 함수 | **배포 배치 진입점** |
| `push_logs` 중복 방지 스키마·색인 | 배치를 부르는 것 (cron) |

`{NAME}` 을 치환하는 코드는 **`db/smoke.mjs` 안의 시험용 문자열이 유일**합니다.
`app.mjs` 의 경로는 4개(`/webhook` `/link/start` `/link/callback` `/health`)뿐이고,
`package.json` 의 스크립트는 `start/migrate/migrate:check/smoke/verify` 로
**배치가 없습니다.**

→ **P4 는 세 덩어리입니다.** 순서를 지키지 않으면 원고를 다시 쓰게 됩니다.

```
P4-a  렌더러      템플릿 + 사용자 → 실제 보낼 메시지        ← 형식이 여기서 확정
P4-b  배포 배치   대상 추출 → 렌더 → 발신 → push_logs
P4-c  원고 101일  a 가 확정한 형식으로 작성
```

**c 를 먼저 하면 안 됩니다.** 렌더러가 확정되기 전 형식으로 101일을 쓰면,
치환 규칙이나 메시지 분할이 바뀔 때 101건을 전부 손봐야 합니다.

## 2. 확정된 형식 (스키마가 이미 정한 것)

```sql
content_templates (
  day_number         INT PRIMARY KEY,   -- 1〜101
  semester           INT NOT NULL,      -- 1〜4  ※ day_number 에서 자동 계산
  grammar_point      VARCHAR(100),      -- "-입니다 / -입니까?"
  grammar_tip_kr     TEXT,              -- 한·일 병기 짧은 설명
  dialogue_template  JSON,              -- [{kr, ja}] 3〜4문
  vocab_3            JSON,              -- [{kr, meaning, note}] ×3
  requires_name_slot BOOLEAN
)
```

학기 구분은 `learning.mjs` 의 `SEMESTERS` 가 **단일 출처**입니다.

| 학기 | 일자 | 일수 |
|---|---|---|
| 1 | 1–30 | 30 |
| 2 | 31–50 | 20 |
| 3 | 51–75 | 25 |
| 4 | 76–101 | 26 |

퀴즈는 **30·50·75일**(`quiz_checkpoints`). 101일은 수료 메시지라 퀴즈 없음.
`upsertTemplate()` 이 `semesterForDay(d)` 로 학기를 스스로 넣으므로,
**원고에 학기를 적지 않습니다** (적으면 두 곳에 진실이 생김).

## 3. P4-a 렌더러 — 먼저 정해야 할 것

### 3.1 치환 슬롯

`smoke.mjs` 에 두 가지가 등장합니다.

```js
dialogueTemplate: [{ kr: "{NAME}입니다.", ja: "{NAME_JP}です。" }]
```

| 슬롯 | 값 | 출처 |
|---|---|---|
| `{NAME}` | 한글 이름 (다나카) | `users.name_kr` |
| `{NAME_JP}` | 일본어 이름 (たなか) | `users.name_reading` |

**결정 필요 ①** — 조사(助詞)를 어떻게 처리할지.

한국어는 받침에 따라 조사가 바뀝니다. `{NAME}입니다` 는 항상 안전하지만,
`{NAME}는/은`, `{NAME}가/이`, `{NAME}야/아` 는 이름마다 달라집니다.

사이트 본체에는 **이미 받침 판정과 조사 선택이 구현되어 있습니다**
(`index.html` 의 `hasJong`/`ieyo`/`ega`, 장면 회화의 `fillName`).
서버에도 같은 규칙이 필요합니다.

- (가) 슬롯을 늘린다 — `{NAME_EUN}` `{NAME_GA}` `{NAME_VOC}` … 렌더러가 받침으로 고름
- (나) 조사 붙는 문장을 쓰지 않는다 — 원고 제약이 커짐

**(가) 를 권합니다.** 사이트에서 이미 검증된 규칙이고, 안 하면 「켄 씨은」 같은
문법 오류를 **학습 콘텐츠로 가르치게 됩니다.** 실제로 사이트에서 한 번 낸 오류입니다.

> 주의 — 조사는 **직전 글자**를 따릅니다. `{NAME} 씨는` 처럼 사이에 말이 끼면
> 그 말(`씨`)에 맞춰야 하므로, 슬롯을 이름 바로 뒤에만 쓰도록 원고 규칙에 못박습니다.

### 3.2 메시지 구성

**결정 필요 ②** — LINE 메시지 몇 통으로 보낼지.

하루치에 문법·회화·단어 3개가 들어갑니다. 한 통에 다 넣으면 길고,
나누면 알림이 여러 번 울립니다. LINE 은 1회 push 에 최대 5통까지 묶을 수 있습니다.

제안: **2통** — ①인사+문법+회화 ②단어 3개.
`pushMessage(to, messages[])` 가 이미 배열을 받으므로 한 번의 호출로 끝납니다.

### 3.3 이름이 없는 사용자

`requires_name_slot = true` 인 날에 `name_kr` 이 비어 있으면 어떻게 할지.

**결정 필요 ③** — (가) 그 날만 이름 없는 대체 문장 (나) 이름 입력 유도 후 보류

`users.name_kanji/name_reading/name_kr` 은 전부 NULL 허용이고,
LINE 만 등록하고 사이트 진단을 안 한 사람이 있을 수 있습니다.

## 4. P4-b 배포 배치

### 4.1 없는 것을 만듭니다

```
db/push-daily.mjs        (신규) 진입점. cron 이 부름
package.json scripts     "push": "node db/push-daily.mjs"
```

`app.mjs` 에 경로로 넣지 않습니다 — HTTP 로 노출하면 외부에서 배포를 유발할 수
있고, 인증을 또 만들어야 합니다. **cron 이 직접 부르는 스크립트**가 단순합니다.

### 4.2 배치가 지켜야 할 것

`push_logs` 스키마 주석에 이미 요구가 적혀 있습니다.

- **하루 2회 실행** — `ix_push_user_type_time` 색인이 그 전제로 설계됨
- **중복 발신 금지** — 같은 날 같은 `push_type` 이 있으면 건너뜀
- **실패도 기록** — `status='failed'`. 안 남기면 「배포가 멈춘 것」을
  이용자 문의로 알게 됨
- **이중 기동 방지** — `verify-server.mjs` 가 이미 검사 중(73항목에 포함)

### 4.3 JST 고정

`lib/jst.mjs` 가 있고 README 에 **「시각은 전부 JST. 서버 시계에 기대지 않습니다」**
라고 적혀 있습니다. 배치도 이를 따릅니다. ChemiCloud 서버 시계가 UTC 여도
「일본의 오늘」로 판정해야 합니다.

## 5. P4-c 원고 101일

### 5.1 분량

```
101일 × (문법 1 + 회화 3〜4문 + 단어 3)
= 문법 101개 · 회화 약 350문 · 단어 303개
```

**한 번에 쓰지 않습니다.** 1학기(30일)를 먼저 쓰고 렌더러·배치로 실제 발신까지
확인한 뒤 나머지를 채웁니다. 형식 문제는 30일치에서 드러납니다.

### 5.2 문법 배열 — 결정 필요 ④

101일을 무엇으로 채울지가 정해져 있지 않습니다. 후보:

- **(가) TOPIK I 문법 순서** — 검증된 순서, 교재와 대조 가능
- **(나) 사이트와 이어지는 순서** — 이름·자기소개에서 출발
  (`저는 {NAME}입니다` → 조사 → 시제 …)

**(나) 를 권합니다.** 사이트가 이미 「이름으로 배우는 한국어」이고,
1일차가 `{NAME}입니다` 로 시작하면 웹에서 LINE 으로 넘어온 사람에게
**같은 이야기의 연속**이 됩니다. (가)는 어느 교재로도 대체 가능한 콘텐츠가 됩니다.

### 5.3 입고 방법

원고를 **JSON 파일로 저장소에 두고**, 스크립트가 `upsertTemplate()` 로 넣습니다.

```
server/content/day-001.json … day-101.json   또는  content/semester-1.json
server/db/seed-content.mjs                   (신규) 입고 스크립트
```

- SQL `INSERT` 를 손으로 쓰지 않습니다 — 원고는 사람이 고치는 것이라
  JSON 이 읽고 쓰기 쉽습니다
- `upsertTemplate` 이 `ON DUPLICATE KEY UPDATE` 이므로 **몇 번 돌려도 같은 결과**
- `findMissingTemplateDays()` 로 빠진 날을 셀 수 있습니다 (이미 구현됨)

**결정 필요 ⑤** — 원고 JSON 을 공개 저장소에 둘지.
콘텐츠는 이 서비스의 자산입니다. 유료 배포물이 저장소에 그대로 있으면 누구나 받습니다.

## 6. 검증 계획

기존 방식(단정문 + 실제 대조)을 따릅니다.

| 대상 | 방법 |
|---|---|
| 슬롯 치환 | 받침 있는 이름/없는 이름 × 전 슬롯. 「켄 씨은」류가 안 나오는지 |
| 학기 계산 | 1·30·31·50·51·75·76·101 경계 |
| 원고 결번 | `findMissingTemplateDays()` 가 0 을 반환 |
| 중복 발신 | 같은 날 두 번 돌려 2회차가 건너뛰는지 |
| 실패 기록 | 발신 실패 시 `status='failed'` 가 남는지 |
| JST | 서버 TZ 를 UTC 로 두고 「일본의 오늘」이 맞는지 |
| 한국어 정확성 | 문법 설명·예문을 사이트 기준(받침·조사)과 대조 |

## 7. 결정이 필요한 것 (착수 전)

| # | 항목 | 제안 |
|---|---|---|
| ① | 조사 슬롯 | **슬롯 확장** (`{NAME_EUN}` 등). 사이트 규칙 재사용 |
| ② | 메시지 통수 | **2통** (문법+회화 / 단어) |
| ③ | 이름 없는 사용자 | 미정 — 대체 문장 or 입력 유도 |
| ④ | 문법 배열 | **사이트와 이어지는 순서** (이름·자기소개 출발) |
| ⑤ | 원고 저장 위치 | 미정 — 공개 저장소 or 비공개 |

**① ② ④ 가 정해지면 P4-a(렌더러)부터 착수할 수 있습니다.**
③⑤ 는 원고 작성 전까지 정하면 됩니다.

## 8. 착수 순서

```
1. ①②④ 결정
2. P4-a 렌더러 + 검증          ← 형식 확정
3. P4-b 배포 배치 + 검증        ← 실제 발신 확인
4. P4-c 1학기(30일) 원고        ← 형식 문제를 여기서 발견
5. 발신 확인 후 2〜4학기(71일)
```

> 서버 배포(ChemiCloud)·폴리시 개정·도메인은 §11 대로 **보류 중**입니다.
> P4-a/b 는 서버를 띄우지 않아도 `db/smoke.mjs` 방식으로 검증할 수 있으므로
> 보류와 무관하게 진행 가능합니다. **실제 발신만 보류에 걸립니다.**
