## 1. 리서치 — 이미 있는 것과 비어 있는 것

**있는 것** (전부 실소스 확인):
- `quiz_checkpoints` 30/50/75 + `isCheckpoint` / `semesterForDay`
- 수신·채점: `action=quiz&day=30&choice=n` → `isCheckpoint` 대조(변조 방어) →
  `lookupAnswer` = **그 날 원고의 `tpl.quiz.answer`** (003 이후 살아 있음) →
  `setQuizResult` 가 학기 단위로 `quiz_pass_log` 에 기록
- `push_type` ENUM 의 `'quiz'`, smoke 의 quiz 로그 시험

**비어 있는 것 2가지:**
1. **발신 코드** — 어디에서도 절목 퀴즈를 보내지 않음
2. **채점 후 답장** — 기존 quiz 분기는 `setQuizResult` 후 결과 객체만 반환하고
   `reply()` 를 부르지 않음. **답한 본인에게 아무것도 안 감.** 이 파일 머리말
   스스로가 「답하면 그 자리에서 돌려준다. 안 돌려주면 답했는데 아무 일도
   없는 것처럼 보인다」고 적어 둔 것과 어긋남 — 발신을 여는 김에 같은
   커밋에서 메움 (발신 없인 안 밟히던 공백이라 지금까지 무해했음)

참고: postback 주석의 「計画書 5-4」는 저장소에 없는 실행계획서 v3 의 절 번호.
남아 있는 설계 사실은 위 코드가 전부이며, 이 계획이 그 취지(절목일 아침에
본편 **뒤에** 더한다 — [repo/learning.mjs](../server/lib/repo/learning.mjs) 節目 주석)를 따른다.

## 2. 설계

```
아침 배신 (deliverOne, 복습 퀴즈 블록과 같은 자리)
  next 가 절목(30/50/75)이고 tpl.quiz 가 있으면
  → 본편 뒤에 1통 (🎯 절목 퀴즈, action=quiz&day=N&choice=i)
  → 송신 성공 후 push_logs 에 push_type='quiz' 기록 (기한예고와 같은 패턴)
  → tpl.quiz 없으면 조용히 빠짐 (운세·복습과 같은 태도)

수신 (기존 그대로 + 답장 1통)
  채점·기록은 기존 코드 무수정. setQuizResult 후:
  → 합격: ⭕ + 「N학기 수료!」  /  불합격: ❌ + 정답 표시
```

- **추가 쿼리 0** — `tpl` 은 이미 그 아침에 끌어와 있고, 퀴즈도 그 안에 있음
- **복습 퀴즈와 충돌 없음** — 복습은 절목일을 이미 비워 둠 (`!isCheckpoint`).
  `isCheckpoint` 를 두 번 묻지 않도록 한 번 재서 변수로 나눔
- **문면**: 복습 렌더러의 내부 조립을 공유하고 머리·action 만 다르게
  (`renderReviewQuiz` / `renderCheckpointQuiz` 가 공통 함수를 씀)

## 4. ★ 결정 — 절목일에 기한예고가 겹치는 아침 → **(가)로 확정 (2026-08-05 승인)**

절목일 아침: 본편 2 + 운세 1 + 절목퀴즈 1 = 4통. **기한예고까지 겹치면 5통** —
LINE 상한과 동률입니다. 복습 퀴즈는 「예고 있는 날은 쉼」(결정④)으로 풀었지만,
절목은 학기당 1회뿐이라 같은 답이 자명하지 않습니다.

| | 안 | 대가 |
|---|---|---|
| (가) | **그 아침만 5/5 허용** — 코드 최소(조건 없음). 학기당 최대 1회, 상한 초과는 아님 | 결정 로그의 「상시 최대 4통」에 예외 1건을 새김 |
| (나) | 예고 있는 아침은 퀴즈를 미루고, `push_logs` 의 quiz 기록을 보며 **다음 아침에** 보냄 | 「절목 지난 뒤 도착하는 절목 퀴즈」가 생기고, 미발송 추적 조건이 코드에 늘어남 |

**추천: (가).** 예고는 잔여일수당 1회뿐이라 겹침 자체가 드물고, 5통은 상한
이내입니다. (나)의 추적 코드는 이 드묾에 비해 무겁습니다. (가)로 가면 README
결정 로그의 해당 항목에 「절목 아침은 예외(학기당 최대 1회 5통)」를 같은
커밋에서 덧붙입니다 — 로그와 코드가 어긋난 채 두지 않습니다.

## 5. 검증 (verify-quiz 확장) — 전부 구현·통과 (12→18항목)

1. [x] 절목일 아침 + `tpl.quiz` 있음 → `action=quiz&day=30` 의 1통이 붙음
2. [x] 그 문면의 data 에 answer 없음
3. [x] 절목일인데 `tpl.quiz` 없음 → 아무것도 안 붙고 본편은 나감 (기존 「절목은 복습을 쉼」 항목에 합침)
4. [x] 같은 아침에 복습 퀴즈(`action=review`)는 **없음**
5. [x] 송신 후 `push_type='quiz'` 가 기록됨 — 실송신 성공 1건 / 실패 0건으로 검증
   (dry-run 은 송신 수전에 내려가므로 구조상 기록 불가)
6. [x] 채점 답장: 합격/불합격 각 1통, `setQuizResult` 는 정확히 1회 (기존 기록 로직 회귀 확인)
7. [x] (가) 예고 겹침 아침: 예고+퀴즈 둘 다 붙고, 퀴즈가 **말미** — quickReply 는
   마지막 1통만 열리므로, 말미가 아니면 답 버튼이 화면에 안 나옴 (구현에서 발견해 §2에 얹은 제약)

구현 메모: 퀴즈 형태 검사는 `usableQuiz`(repo/learning.mjs)로 추출해 복습(`pickReviewQuiz`)·
절목 발신(push-daily)·절목 채점(postback `lookupAnswer`) 3곳이 같은 검사를 쓴다.

## 6. 제외 이유

- **재도전** — `quiz_pass_log` 는 학기당 1칸이라 재도전을 넣으면 「몇 번 만의
  합격인가」가 사라짐. 정책(몇 회까지·간격)이 정해진 뒤 별도 계획으로
- **수료 조건 연동** — 현재 `quiz_pass_log` 는 아무도 읽지 않음(§1). 수료를
  퀴즈 합격에 걸지 여부는 사업 결정이라 대표님 몫
- **원고 백필** — 30/50/75 의 quiz 가 입고될 때까지 발신은 조용히 빠짐.
  코드가 먼저 나가도 무해 (복습 퀴즈와 동일)
