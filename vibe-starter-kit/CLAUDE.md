# CLAUDE.md

이 파일은 Claude가 이 프로젝트에서 **가장 먼저 읽는 지침서**입니다.
코드를 작성하기 전에 반드시 이 문서를 끝까지 읽고, 아래 규칙 로딩 절차를 따르세요.

## 1. 기술 스택 (변경 금지 — 바꾸려면 사용자 승인 필요)

| 영역 | 스택 |

| 백엔드 | Python 3.11+ / FastAPI / SQLAlchemy 2.x / Alembic / Pydantic v2 |

**임의로 다른 라이브러리를 추가하지 마세요.** 필요하면 먼저 이유를 설명하고 승인을 받으세요.

## 2. 규칙 로딩 절차 (필수)

작업을 시작하기 전에 **작업 영역에 맞는 규칙 파일만** 읽으세요.
전체를 다 읽지 말고, `.claude/skills.rules.json`의 매핑을 따르세요.

| 건드리는 것 | 반드시 먼저 읽을 파일 |
|---|---|
| `backend/` 아래 무엇이든 | `.claude/rules/backend/01-folder-structure.md` + 해당 영역 규칙 |
| API 엔드포인트 | `.claude/rules/backend/04-api-design.md` |
| DB 모델·마이그레이션 | `.claude/rules/backend/05-database.md` |

## 3. 작업 순서 (이 순서를 바꾸지 마세요)

```
1. 계획 세우기      → 무엇을, 어떤 파일에, 어떤 순서로
2. 계획 검토        → .claude/agents/plan-reviewer.md 에이전트 호출
3. 모르는 것 조사   → .claude/agents/researcher.md 에이전트 호출
4. 규칙 읽기        → 위 2번 표
5. 코드 작성
6. 자체 점검        → 아래 6번 체크리스트
```

**3개 파일 이상을 만들거나 고치는 작업이면 1~3단계를 건너뛰지 마세요.**

## 4. 절대 하지 말 것

1. **파일 위치를 임의로 정하지 않기.** 규칙 문서에 없는 위치면 물어보세요.
2. **같은 기능을 두 곳에 만들지 않기.** 만들기 전에 `grep`으로 기존 구현을 먼저 찾으세요.
3. **색상·폰트크기·간격을 코드에 직접 쓰지 않기.** 반드시 디자인 토큰만 사용.
4. **계층 건너뛰지 않기.** API가 DB를 직접 호출하면 안 됩니다. (`04-api-design.md` 참고)
5. **`.env` 값을 코드에 하드코딩하지 않기.**
6. **요청하지 않은 파일을 만들지 않기.** README, 예제, 데모 파일 임의 생성 금지.
7. **기존 파일을 통째로 다시 쓰지 않기.** 바뀌는 부분만 수정.
8. **마이그레이션 파일을 손으로 수정하지 않기.** Alembic으로 생성하세요.

---

## 5. 반드시 지킬 것

1. 새 기능은 **`backend/app/domain/<기능명>/`** 폴더 하나로 시작합니다.
2. 함수·변수·파일 이름은 `.claude/rules/*/02-naming.md`를 따릅니다.
3. 에러는 반드시 `backend/app/errors/`의 정의된 예외를 씁니다. 맨 `raise Exception` 금지.
4. 새 화면은 `frontend/src/app/`, 재사용 부품은 `frontend/src/components/`.
5. 작업이 끝나면 **바뀐 파일 목록**을 한 줄씩 보고합니다.

## 6. 작업 완료 전 자체 점검 체크리스트

코드를 다 쓴 뒤 아래를 스스로 확인하고, 응답 마지막에 결과를 적으세요.

- [ ] 새로 만든 파일이 규칙에 정해진 위치에 있는가
- [ ] 하드코딩된 색상(`#`)·픽셀값·문자열 상수가 없는가
- [ ] 계층 순서(api → service → domain → db)를 지켰는가
- [ ] 에러 처리가 정의된 예외를 쓰는가
- [ ] 기존에 같은 일을 하는 코드가 이미 있지 않은가
- [ ] 테스트가 필요한 로직인데 테스트를 빠뜨리지 않았는가
