## 2. 이 저장소의 실제 제약

```
index.html      진단 앱 본체 (CSS·JS 인라인, 자체 완결)
privacy.html    プライバシーポリシー
contact.html    お問い合わせ
tips.html       豆知識 (.tip 컴포넌트)
404.html
page.css        문서 페이지 3장이 공유
kanji.json      상용한자 2,136자 (지연 로딩)
```

- **빌드 도구 없음.** `package.json`도 번들러도 없다. `tools/build-site.sh`가 공개 파일을 `dist/`에 모으는 것이 전부
- **배포**: `main` push → GitHub Actions → rsync → Xserver. `tools/build-site.sh`의 `PUBLIC` 배열에 넣지 않은 파일은 배포되지 않음
- **`.htaccess`가 확장자 없는 URL을 처리**. 새 페이지 `omikuji.html`은 `/omikuji`로 접근됨 (별도 설정 불필요)
- **이미 갖고 있는 것** — 재활용 가능:
  - 자음오행 매핑 (`ㄱㄲㅋ→木` …) + 오행 설명 5종
  - 십이지(띠) 계산
  - 한자 → 한국 한자음·훈음 2,136자
  - 한자어 수사 변환 (`1995 → 천구백구십오`)
  - 받침 판정 → 조사 자동 선택
  - Canvas 공유 카드 생성 (1080×1350) + SNS 공유 경로

## 3. 사주 엔진 — KASI API가 필요 없는 이유

원안은 KASI에서 **일별 간지**를 받아 테이블로 만듭니다. 하지만 사주 4주는 성질이 다릅니다.

| 기둥 | 계산 방법 | 외부 데이터 필요? |
|---|---|---|
| **일주(日柱)** | 기준일로부터의 경과일 `% 60` | **불필요** — 순수 산술 |
| **연주(年柱)** | 입춘 경계로 연도 판정 후 `% 60` | 절기 시각만 필요 |
| **월주(月柱)** | 12절(節) 경계로 월 판정 | 절기 시각만 필요 |
| 시주(時柱) | 일간 + 시진 | 불필요 (진태양시 보정 시 경도 필요) |

즉 **필요한 외부 데이터는 24절기 시각뿐**입니다.

```
원안:   1930~2030 일별 간지   = 36,900행  ≈ 1.1MB (gzip 200KB)
개정:   1930~2030 절기 시각   =  2,424행  ≈  40KB (gzip 12KB)
```

절기 시각은 **태양황경이 15° 배수가 되는 순간**으로 정의되며 천문 계산으로 구합니다.
간이 VSOP87 수준이면 오차 1분 이내로, 절기 경계 판정에는 충분합니다.

### 산출물

```
tools/build-solar-terms.py   →   solar-terms.json
```

- 오프라인 계산. **API 키·시크릿·PR 검토 흐름 불필요**
- `tools/build-kanji-json.py`와 동일한 패턴(로컬 실행 → 결과 커밋)

### 검증 (필수)

절기 시각과 **일주 기준일(epoch)** 은 틀리면 모든 결과가 어긋나므로, 구현 전에 먼저 확정하고 검증합니다.

1. 공표된 절기 시각(한국천문연구원 역서, 일본 국립천문대 暦要項)과 **연 24개 × 표본 10개년** 대조 — 허용 오차 ±2분
2. 일주 epoch를 **서로 다른 만세력 3곳**과 대조. 임의 날짜 20건 일치 확인
3. 절기 경계 전후 1일 케이스(입춘·경칩 등)에서 월주가 올바르게 넘어가는지

> **이 검증이 끝나기 전에는 콘텐츠 구현에 들어가지 않습니다.** 계산이 틀린 채로 문구를
> 얹으면 나중에 전부 다시 만들어야 합니다.

### 시주(時柱) — 1단계 제외 권장

진태양시 경도 보정 + 1948~1988년 서머타임 + 조자시/야자시는 **구현·검증 비용이 나머지 전부와 맞먹습니다.**
이 사이트는 프라이버시 폴리시에 「エンターテインメント目的のコンテンツ」라고 명시했고,
사용자는 출생 **시각**을 대개 모릅니다.

→ **1단계는 연·월·일주 기반 오행 비율까지.** 시주는 별도 파일로 분리해 나중에 켤 수 있게 설계.

## 4. ⚠️ localStorage — 프라이버시 폴리시와 정면 충돌

원안은 사용자의 생년월일시를 `localStorage`에 저장해 여러 기능이 공유하는 것을 전제합니다.
**현재 폴리시는 그것을 명시적으로 부정합니다.**

> `privacy.html` 1항:
> - 「Cookie・localStorage 等への保存も行いません」
> - 「ページを閉じた時点で入力内容は完全に消去されます」
>
> `index.html` 입력창 아래:
> - 「入力されたお名前・生年月日は**保存されません**」

이 문구는 이 사이트가 일본인 사용자에게 내세우는 **핵심 신뢰 장치**입니다.
개인정보에 민감한 사용자가 이탈하지 않도록 하는 것이 전환율에 직접 영향을 준다는 판단으로 넣었습니다.

### 선택지

| 안 | 내용 | 대가 |
|---|---|---|
| **A. 저장하지 않음** | 페이지마다 생년월일을 다시 입력 | 폴리시 유지. UX 마찰 |
| **B. 명시적 동의 후 저장** | 「이 기기에 저장하시겠습니까?」 체크 → 저장. 삭제 버튼 제공 | 폴리시 개정 필요. 문구를 정확히 다시 써야 함 |
| **C. URL 파라미터 전달** | `?b=19920101` 로 페이지 간 전달 | 저장 아님(폴리시 유지). URL에 생년월일이 남음 — 공유 시 노출 위험 |

**B를 권장하되, 반드시 폴리시를 같은 커밋에서 고쳐야 합니다.**
GA4·Clarity 추가 때 이미 두 번 겪은 패턴입니다 — 도구를 붙이면서 폴리시를 그대로 두면
**폴리시가 즉시 거짓 문서**가 됩니다.

C는 겉보기엔 안전해 보이지만, 사용자가 결과 URL을 SNS에 공유하면 생년월일이 그대로 노출됩니다. 권하지 않습니다.

## 5. 페이지 구성

라우터가 없으므로 **독립 HTML**로 만듭니다. `.htaccess`가 확장자 없는 URL을 처리하므로 추가 설정은 없습니다.

| 파일 | URL | 성격 |
|---|---|---|
| `omikuji.html` | `/omikuji` | おみくじ × 토정비결 — **랜덤 추첨** 체험 |
| `gilbang.html` | `/gilbang` | 恵方 × 길방 — **방위** 진단 |
| `amulet.html` | `/amulet` | 오행 부적 메이커 — **제작·다운로드** |
| `index.html` (수정) | `/` | 상단에 「오늘의 운세」 위젯 |

역할이 겹치지 않도록 성격을 분리합니다 (원안의 구분을 그대로 채택):

- **오미쿠지** = 매번 결과가 다른 추첨 (문화 비교가 목적)
- **길방** = 오늘/올해의 길한 방위
- **오늘의 운세** = 내 사주 기반 일일 종합운

### 공통 구현 방침

- `page.css`를 공유하고, `.tip` 컴포넌트처럼 **재사용 가능한 부품**으로 스타일 추가
- 각 페이지에 AdSense·GA4·Clarity 3종 태그 (404 제외 규칙과 동일)
- canonical·OG·sitemap 등록 — `tools/set-site-url.py`의 `TARGETS` 배열에 새 파일 추가 **필수**
  (빠뜨리면 도메인 이전 시 그 페이지만 옛 호스트를 가리킴)
- `tools/build-site.sh`의 `PUBLIC` 배열에 추가 **필수** (안 하면 배포되지 않음)

### 크롤러 대응

이 사이트의 콘텐츠는 JS로 생성되므로, AdSense 심사에서 **빈 페이지로 보이는 문제**를 이미 한 번 겪었습니다.
새 페이지도 같은 함정이 있습니다.

→ `index.html`의 `#about`처럼, 각 페이지에 **입력 전에도 읽히는 정적 해설**을 반드시 넣습니다.
「오미쿠지란 무엇인가 / 토정비결이란 무엇인가 / 둘의 차이」 같은 문화 해설은
그 자체로 좋은 콘텐츠이면서 크롤러 대응이 됩니다.

## 6. 한국어 학습 레이어 — 현실적 범위

원안은 `word-collector.js`(단어장)·`voice-spell.js`(발음 체크)·`daily-stamp.js`(출석)에 연동한다고 했으나,
**이 저장소에는 셋 다 없습니다.** 새로 만들지, 생략할지 결정이 필요합니다.

| 기능 | 신규 구현 비용 | 비고 |
|---|---|---|
| 어휘 카드 (뜻풀이·발음 표기) | **낮음** | 정적 데이터. `index.html` STEP 3에 이미 유사 구현 있음 |
| 발음 재생 | **낮음** | `SpeechSynthesis` API (`ko-KR`). 브라우저 내장, 외부 요청 없음 |
| 단어장 저장 | 중간 | **localStorage 필요** → §4 결정에 종속 |
| 출석 스탬프 | 중간 | 동일 |

**권장**: 1단계는 **어휘 카드 + 발음 재생**까지. 저장 기능은 §4가 정해진 뒤.

어휘 데이터 스키마는 원안 것을 거의 그대로 씁니다 (이미 잘 설계됨):

```js
{
  korean: "액운을 물리치소서",
  roman:  "aegun-eul mullichisoseo",
  ja:     "厄をお祓いください",
  parts: [
    { w: "액운(厄運)", m: "厄運・悪い運" },
    { w: "물리치다",   m: "追い払う" },
    { w: "-소서",     m: "祈願を表す古語の語尾" }
  ],
  grammar: "「-소서」は古い祈願文の終結語尾。現代の「〜してください」の格式体にあたります。"
}
```

- `topikLevel`은 **뺍니다** — 기존 레벨 체계가 없어 붙일 기준이 없습니다
- `audio` 경로도 **뺍니다** — `SpeechSynthesis`로 대체

## 7. 단계별 범위

원안을 한 번에 다 하면 검증되지 않은 사주 계산 위에 4개 기능이 얹힙니다. 나눕니다.

### 1단계 — 계산 기반 확보 (콘텐츠 없음)

```
tools/build-solar-terms.py   절기 시각 생성
solar-terms.json             산출물
docs/saju-verification.md    검증 결과 기록
```

**§3의 검증 3종을 통과하는 것이 완료 조건.** UI는 만들지 않습니다.

### 2단계 — 오미쿠지 × 토정비결

사주 계산에 의존하지 않는(랜덤 추첨) 기능이라 **1단계와 병행 가능**합니다.
문화 비교 해설 + 어휘 카드 + 발음 재생. 가장 먼저 내놓기 좋습니다.

### 3단계 — 오늘의 운세 + 길방

1단계 완료 후. 오행 산출이 필요합니다.

### 4단계 — 부적 메이커

Canvas 렌더링은 공유 카드 구현을 재활용할 수 있습니다.
웹폰트(캘리그래피)는 **용량과 외부 요청**을 늘리므로 필요성을 다시 판단합니다
— 현재 사이트는 시스템 폰트만 쓰고 외부 폰트 요청이 0건입니다.

## 8. 결정이 필요한 것

구현 전에 답이 필요한 순서대로 적습니다.

1. **§4 생년월일 저장** — A(저장 안 함) / B(동의 후 저장 + 폴리시 개정) / C(URL 전달) 중 어느 것인가
   → 이것이 정해져야 페이지 간 데이터 흐름이 결정됩니다
2. **시주 포함 여부** — 1단계 제외(권장) / 포함
3. **단어장·출석 기능** — 만들 것인가 / 어휘 카드만으로 갈 것인가
4. **부적 웹폰트** — 캘리그래피 폰트를 위해 외부 요청을 추가할 가치가 있는가
5. **착수 순서** — 2단계(오미쿠지)를 먼저 내놓고 반응을 볼지, 1단계(계산 기반)부터 다질지

## 9. 검증 계획

기존 방식을 그대로 씁니다 — jsdom 단정문 + 실제 배포 후 스모크 테스트.

| 대상 | 방법 |
|---|---|
| 절기·일주 계산 | 공표 자료 대조 (§3) |
| 페이지 구조·링크·메타 | jsdom (`chk.js` 패턴) |
| 어휘 카드 조사 처리 | 받침 유무별 케이스 |
| 정적 콘텐츠 분량 | JS 미실행 시 본문 글자 수 측정 |
| 배포 | `tools/build-site.sh` + Actions 스모크 테스트에 새 URL 추가 |

**스모크 테스트에 새 페이지 URL을 추가하는 것을 잊지 말 것** —
`/omikuji`, `/gilbang`, `/amulet`이 200을 반환하는지 확인해야 `.htaccess` 누락을 잡습니다.

## 10. 원안 대비 요약

- **KASI API·시크릿·전용 워크플로 — 불필요.** 절기 시각만 있으면 되고 오프라인 계산 가능
- **테이블 용량 1/20** (gzip 200KB → 12KB)
- **localStorage는 폴리시 개정 없이는 쓸 수 없음** — 원안에 없던 제약
- **학습 모듈 재사용 불가** — 어휘 카드·발음 재생은 신규 구현, 저장 기능은 §4에 종속
- **시주 보정은 1단계에서 제외** 권장
- 문화 비교·역할 구분·어휘 스키마 등 **원안의 콘텐츠 설계는 대부분 그대로 유효**
