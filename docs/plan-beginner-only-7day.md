## 0. 먼저 — 지금 코드가 어떻게 되어 있는가

읽고 확인한 사실만 적습니다.

| 사실 | 위치 |
|---|---|
| `TRIAL_DAYS = 7` **이미 7일**（3→7 전환이 `main` 에 들어와 있음） | `repo/billing.mjs:29` |
| 패키지는 **이미 7의 배수**（7·14·21·28일 = ¥500·970·1410·1800） | `repo/billing.mjs:22` |
| 코스 목록을 만드는 곳은 **딱 2곳**, 둘 다 `TRACKS` 를 돌며 원고 수로 거른다 | 아래 |
| 원고가 7일분 미만인 코스는 **이미 자동으로 빠진다** | 같은 2곳 |

```js
// checkout.mjs:123 — 가격표 입구（리치메뉴 [受講料] · 「受講料」 타이핑 둘 다 여기)
export async function sellableTracks(conn) {
  for (const t of TRACKS) if (sellablePackages(await learning.countTemplates(conn, t)).length) out.push(t);
}
// onboarding.mjs:281 — 온보딩 코스 선택
for (const t of TRACKS) if (TRIAL_DAYS <= await countTemplates(conn, t)) selectable.push(t);
```

**그래서 지금 3코스가 다 보이는 이유는 「원고가 3코스 다 들어 있어서」입니다.**
중급·상급 원고를 지우면 자동으로 빠지지만, 그건 원고를 버리는 일이라 하지 않습니다.
**「원고는 있지만 아직 팔지 않는다」를 표현하는 자리가 지금 코드에 없습니다.** ①은 그
자리를 하나 만드는 일입니다.

## ① 초급만 표기

### 접근

`repo/learning.mjs` 에 **「지금 제공하는 코스」 목록 하나**를 신설하고, 위 2곳이
그것을 통과하게 합니다.

```js
// repo/learning.mjs
export const TRACKS = Object.freeze(["beginner", "intermediate", "advanced"]);

/* いま募集しているコース。TRACKS とは別に持つ ── TRACKS は
   「この系で存在しうる値」で、entitlements・purchases・原稿・
   既存利用者の active_track がすべてこれで検証される。ここを削ると
   中級・上級を持っている人の行が「未知の track」になり、配信が止まる。
   募集を止めるのは表示の話なので、別の名前で別に持つ。 */
export const OPEN_TRACKS = Object.freeze(["beginner"]);
export const isOpenTrack = (t) => OPEN_TRACKS.includes(t);
```

```diff
 // checkout.mjs sellableTracks
-  for (const t of TRACKS) {
+  for (const t of OPEN_TRACKS) {

 // onboarding.mjs askTrackStep
-  for (const t of TRACKS) {
+  for (const t of OPEN_TRACKS) {
```

### 목록에서 빼는 것만으로는 부족합니다

`postback` 의 `data` 는 **이용자 단말을 거쳐 돌아오므로 고쳐 보낼 수 있습니다.**
이 저장소는 이미 같은 이유로 원고 수를 각 입구에서 **다시** 검사합니다
（`postback.mjs:379` 의 「data は書き換えられる」 주석). 같은 자리에 코스 검사도 넣습니다.

| 입구 | 지금 막는 것 | 추가 |
|---|---|---|
| `onPlan`（가격표） | 판매 게이트·원고 수 | `isOpenTrack` |
| `onBuy`（결제, 구버전 경로） | 판매 게이트·원고 수 | `isOpenTrack` |
| `onTrackpick`（온보딩 선택） | 원고 수 | `isOpenTrack` |
| `onTrial`（체험 시작） | 원고 수 | `isOpenTrack` |

막았을 때의 응답은 **기존 `coursePreparing(track)`** 을 그대로 씁니다
（「〇〇는 준비 중입니다」）— 새 문면을 만들지 않습니다.

### 건드리지 않는 것 — 중요

- **`TRACKS` 자체는 그대로.** 여기서 지우면 `isTrack()` 이 중급·상급을 「미지의 값」으로
  보고, **이미 중급·상급을 가진 사람의 배신·채점·진도가 멈춥니다.**
- **이미 보유한 코스는 계속 배신됩니다.** `OPEN_TRACKS` 는 「새로 고르거나 살 수 있는
  코스」만 좁힙니다. 배신 경로(`push-daily`/`push-evening`)는 손대지 않습니다.
- 원고(중급·상급 101일씩)는 서버에 그대로 둡니다. 다시 열 때 `OPEN_TRACKS` 한 줄입니다.

> **확인 부탁**: 중급·상급을 **이미 보유·수강 중인 분**이 계십니까?
> 계신다면 위 설계 그대로(계속 배신). 안 계시면 결과는 같지만, 알고 진행하는 편이 낫습니다.

### 넣을 자리 — 2곳 제안

**(가) 가격표 `priceList`** — 값을 보는 순간 (필수)

```diff
-      `全 ${TOTAL_DAYS} 日で1つの講座です。`,
+      `全 ${TOTAL_DAYS} 日で1つの講座です。`,
+      "受講料は 7 日分ずつのお申し込みです（7・14・21・28 日分）。",
```

**(나) 코스 선택 `askCourse`** — 고르기 전에 (선택)

체험 안내와 함께 「이후는 7일분씩」이 보이면, 체험 7일 → 이후 7일씩이 한 줄로 이어집니다.

### 확정이 필요합니다

문면은 대표님 것입니다. 위 일본어는 **후보**이며, 확정해 주시면 그대로 넣습니다.
（예: 「7日分ずつのお申し込みです」 / 「7日単位でお申し込みいただけます」 / 그 밖）

**(나)를 넣을지도 지시해 주십시오.** 안 넣으면 가격표에만 나옵니다.

## ③ 무료 7일 동안 결제 금지

### 지금은 살 수 있습니다

체험 중에도 `[受講料]` → 가격표 → 결제까지 **전부 열려 있습니다.**
오히려 체험 6일째（`TRIAL_UPSELL_DAY = TRIAL_DAYS - 1`) 저녁에는
**이쪽에서 먼저 권합니다**（`trialUpsellNotice`, 「受講料を見る」 버튼 포함).

### 접근 — 게이트 1개를 추가

`salesAllowedFor`（판매 모드·법정표시）는 그대로 두고, **그 뒤에** 체험 중 판정을 놓습니다.

```js
/* checkout.mjs
   無料体験の 7 日が終わるまでは決済へ進ませない（대표 지시 2026-08-10）。
   判定は日付と残日数の **両方**。片方だけだと:
     残日数だけ … 配信が止まっている人（ブロック・障害）は days_used が
                  進まないので、体験がいつまでも終わらず永久に買えない
     日付だけ  … 障害で配信が遅れた人が、無料日数を残したまま買える */
export function inTrialNow(sub, remaining, today = jstDate()) {
  if (!sub || sub.payment_status !== "trial") return false;
  return remaining > 0 && today <= sub.trial_end;
}
```

막는 자리는 **결제로 이어지는 3곳 전부**（1곳이라도 새면 그리로 갑니다 —
`checkout.mjs` 머리말의 「4 か所とも salesAllowedFor を通す」와 같은 이유）:

| 입구 | 동작 |
|---|---|
| `onPlans` | 코스 목록 대신 「체험 중」 안내 |
| `onPlan` | 가격표를 만들지 않음（Stripe 세션도 안 만듦) |
| `onBuy` | 결제 세션 거부 |
| `message.mjs` 「受講料」 타이핑 | `onPlans` 와 같은 판정·같은 응답 |

### 새 문면 1개가 필요합니다

```
無料でお試しいただける 7 日分をお届けしている間です。
7 日分が終わりましたら、続きのご案内をお送りします。
```

**「終わりましたらお知らせします」라고 써도 되는 이유** — 이 저장소는 지킬 수 없는 약속을
문면에 쓰지 않습니다（`checkout.mjs:143` 「約束した瞬間、文書がコードより先へ出る」).
그런데 이 약속은 **코드가 실제로 지킵니다**: 잔여 0이 된 아침에 `upsellNotice` 가
1회 나갑니다（`push-daily`, 이탈 에피소드당 1회). 판매가 열리는 날을 알릴 방법이
없던 그 경우와 다릅니다.

### ★ 6일째 저녁 권유가 앞뒤가 안 맞게 됩니다

`trialUpsellNotice`（체험 6일째 저녁）는 지금 **「下から日数を追加できます」+ 受講料 버튼**을
보냅니다. 결제를 막으면 **그 버튼을 누른 사람이 「체험 중입니다」 벽을 봅니다.**

선택지:

- **(가) 권유를 「예고」로 바꾼다** — 버튼 없이 「明日が最後の 1 日です。終わりましたら
  続きのご案内をお送りします」. 누를 곳이 없으니 헛손질도 없습니다（이 저장소가 이미
  `canBuy === false` 쪽에서 쓰는 방식: 「押す所が無ければ空振りも無い」）
- (나) 6일째만 예외로 결제를 연다 — 지시(「7일분에서는 결제 진행 안 됨」)와 어긋납니다
- (다) 그대로 둔다 — 벽을 보게 됩니다. **권하지 않습니다**

**(가)를 기본안으로 합니다.**

### 트레이드오프 — 짚어 둡니다

- 3일째에 「좋다, 지금 사겠다」는 사람이 **그 자리에서 살 수 없습니다.** 결제 의사가
  가장 높은 순간과 결제 가능 시점이 어긋납니다. 지시대로 진행하되, 이건 매출 쪽 비용입니다
- 체험 종료 후 결제까지 **하루가 빕니다** — 7일째 아침에 마지막 배신 → 그날은 잔여 0이
  아직 아님 → 다음 날 아침 `upsellNotice`. 「체험이 끝난 그날 저녁에 바로 안내」가
  필요하면 별건으로 설계해야 합니다（이번 범위 밖)
